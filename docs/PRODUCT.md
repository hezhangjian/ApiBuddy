# 产品范围

## 已确定的体验原则

- 先让用户快速跑通一个真实请求，再展开工程细节；说明以可以复制的命令和实际操作为主。
- 服务 ID 让用户输入并预览命令；始终使用 `apibuddy orders` 形式，避免每个服务生成不同可执行文件。
- Agent 接入先提供一段能粘贴到任意 Markdown 的说明，不要求用户理解额外注册协议，也不自动修改 Agent 配置。

## 当前能力

ApiBuddy 面向个人日常 HTTP 调试，当前交付一个完整的请求模板循环：

1. 创建服务时填写名称与服务 ID（例如 orders），输入时预览 apibuddy orders <接口名>；选择服务后点击「新建接口」，通过弹窗填写名称、方法和路径/URL，创建后立即保存到列表并打开编辑器。
2. 写入 {{变量名}}，设置默认值并查看请求预览。
3. 命名、描述并保存到本地模板库。
4. 再次加载，修改变量后发送；可只临时执行，也可保存更新或另存副本。
5. 查看响应状态、耗时、Body、Headers 和 Raw，必要时取消或复制结果。
6. 生成统一 apibuddy CLI，通过服务标识和接口名调用；未保存模板的路径也能通过 request 调用。面板列出全部接口的示例，一键复制给 Agent。

左侧模板库按服务隔离，支持搜索和刷新，左下角显示实际存储目录。保存采用独立 JSON 文件，无数据库服务依赖。

新建接口会复用服务地址并补齐路径中的变量；有变量时进入变量页，普通 GET/HEAD 进入参数页，其他方法进入正文页。取消不改变原编辑内容；保存失败保留弹窗输入，可修正后重试。新建前仍提供未保存修改提示。

当前不包含：团队协同、服务内文件夹、服务编辑/删除、环境集、秘密管理、脚本、OpenAPI/cURL 导入导出、历史记录、二进制文件、SSE 协议解析和自动更新。
